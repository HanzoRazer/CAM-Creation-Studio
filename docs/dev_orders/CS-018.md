## Outcome

Make the generated rectangle's computational geometry and declared metadata
reproducible from its captured inputs. Remove edge-order-dependent signed
zero from normalized planner coordinates, and re-derive candidate metadata
before accepting its digest and fixture review.

This is a correction to generated-plan identity. It is not another contour
planner and it is not an operational authorization increment.

## Findings that remain after CS-017

The merged CS-017 work already closed the output-overlap, symlink,
partial-publication, unreadable-review, overflowing-number, and
sequence-test findings. Those patches are not reissued.

1. Equal-valued `-0.0` and `0.0` can make rectangle normalization and
   generated candidate serialization depend on edge enumeration order, even
   when the G-code is unchanged.
2. `replan_matches` regenerated motion but passed candidate-supplied tool and
   material metadata back into the digest. Recomputing a digest from those
   claims is not independent metadata verification.

The second issue is an internal consistency defect. A normal package-byte
workflow does not expose a way to manufacture that candidate. This order
does not claim to secure a Python process against arbitrary code execution
or private-seal access.

## Decisions

Signed zero is local computational normalization. After a coordinate is
validated as finite, a numeric zero becomes positive floating-point zero.
Any other value keeps its magnitude and precision. The helper runs on
rectangle endpoint tuples before extrema, undirected edge lookup, and
normalized bounds and poses. It does not add an epsilon, snap a near-zero
value, repair a gap, coerce a string or bool, or modify captured source
bytes.

Captured artifact identity stays exact-byte SHA-256. Normalized
computational motion is independent of equivalent endpoint signs and edge
order. Complete candidate provenance still binds the actual source bytes, so
different source files keep different provenance digests.

Initial construction and export-time revalidation share one derivation from
the verified request and the captured planner-input and operation-plan
bytes. The public constructor is not called from the check, and the check
does not assign the generation seal. Disagreement is `PLAN_CHANGED`.
Changed captured files stay `SNAPSHOT_CHANGED`. Failed byte bindings stay
`DIGEST_MISMATCH`.

The rectangular planner version moves from `1` to `2`. The planner id and
motion-source tag stay the same. The local policy digest includes the
supported version and the changed validation semantics, so an older
generated-plan fixture review is not migrated. New runtime records emit
version `2`. Historical version `1` remains inspectable and does not
authorize export. The explicit-motion `/1` path stays planner identity
`unavailable`.

Operational export stays disabled. Outputs retain
`EXPERIMENTAL — NOT FOR MACHINING`. Fixture reviews remain
`fixture_binding_only`. No manufacturing feed ceiling is chosen here. The
recorded `1e300` feed limitation stays an explicit separate policy question.
